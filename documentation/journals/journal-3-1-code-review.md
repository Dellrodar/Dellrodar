An ePortfolio can help with self-promotion because it gives employers more than a list of skills on a resume. It lets me show the work itself and explain how I approached it. For this project, I can demonstrate how I am rebuilding an older animal shelter dashboard as a full-stack application with React, FastAPI, PostgreSQL, authentication, and role-based access control. In an interview, I could use the repository, code review, screenshots, and enhancement narratives to explain what I changed and why. There are also risks to making work public, including exposing credentials, private data, security weaknesses, or intellectual property I do not have permission to share. I can reduce those risks by only publishing authorized work, removing secrets and personal data, checking the commit history, and limiting the portfolio to what is needed to demonstrate my skills.

So far, I have made the strongest progress toward outcomes two, four, and five through the application structure, documentation, authentication, administrator account, and backend permission checks. I have also started working toward outcome three by separating the frontend, backend, and database responsibilities and planning how the rescue matching feature will filter, score, rank, and paginate results. That outcome is still in progress because the matching logic and full animal data model are not complete. Outcome one also remains in progress because most of the work has been completed independently, although instructor feedback and later revisions will help demonstrate collaboration. The initial software design and engineering enhancement is complete for milestone one, while the algorithms and database enhancements are the main focus of the upcoming milestones.
